Thirteen new Candidate Footguns: ten from Nyx's 2026.11 batch (bugs found and fixed on a live install, proven on a test box first) and three from a review of the HA release notes for 2026.5 through 2026.11.1. Every factual claim in the new and changed entries was checked against the current HA docs and, where the docs are silent, HA core source, and the claims neither could settle were tested on a live HA 2026.11.0 box (see Verification). Changes from Nyx's drafts made in review:

- **FG-44:** added the "read the response directly" correct form and a cross-reference to FG-33/FG-34.
- **FG-45:** flagged as standard Jinja2 scoping rather than an HA addition. Kept because HA templates are where users hit it.
- **FG-46:** severity lowered to soft_fail: either policy for internal callers is acceptable, and what is scored is having an explicit rule for the empty case. Added the docs rule that `context` is only available in actions.
- **FG-47:** the correct form now distinguishes existence (`states[x] is not none`) from availability (`has_value()`).
- **FG-48:** added `delay_off` on a template binary sensor as the first correct form, and completed the trigger-based form with a `state:`.
- **FG-49:** the `for:` correct form had no from/to filter, which broke FG-43. Fixed.
- **FG-50:** reframed around the HA-native fix (send only the change; a trigger-based template entity merges it) instead of a ZenOS-style keyed store.
- **FG-51:** added `script.turn_on` to a worker script as a correct form.
- **FG-52:** deprecation start corrected to 2026.10 from the release notes. Removal in 2027.10 confirmed in HA source; `end_type` set to `hard_break` (Nyx's `"removal"` was not a valid value). Detection widened to `config_entries_subentries` and `primary_config_entry`.

### From the HA release notes

| FG | Title | Severity | HA |
|---|---|---|---|
| FG-54 | Sun and calendar trigger positive offset without offset_type changed direction | hard_fail | 2026.11 |
| FG-55 | Matching on friendly_name instead of entity_id or the name functions | soft_fail | 2026.11 |
| FG-56 | Removed or renamed purpose-specific trigger and condition keys | hard_fail | 2026.5–2026.7 |

- **FG-54:** HA 2026.11 (PR #184855): `sun.*`, `calendar.event_started` and `calendar.event_ended` triggers used to default to `offset_type: before`. Now the sign decides. YAML written with a positive offset and no `offset_type` silently fires on the other side of the event. `offset_type` is still accepted and folded into the sign; the classic `trigger: sun` is unaffected.
- **FG-55:** the 2026.11 naming change and child devices change some `friendly_name` values. Entity IDs do not change. HA recommends `entity_name()`, `device_name()` and `area_name()` and plans to deprecate `friendly_name`.
- **FG-56:** `entered_home`/`left_home`/`is_home`/`is_not_home` removed in 2026.5; Labs `any`/`last` renamed in 2026.6; ten purpose-specific keys renamed in 2026.7. The old keys stop working.

## Verification

Checked against the HA docs (build 2026.11.1) and, where the docs are silent, HA core source (`dev`, 2026-11-11).

**Corrected from the earlier draft**

- FG-21: oversized attributes are lost from recorder history, not from live state or restart restore (source: `recorder/db_schema.py`, `helpers/restore_state.py`; docs: template integration).
- FG-34: lowercase `true`/`false`/`none` stay text; only `True`/`False` become booleans (docs: templating/types).
- FG-41: `as_datetime` raises for non-text invalid input (docs). Date-only text was unsettled by docs and source; T5 showed it parses (see below).
- FG-43: docs state from/to/`to: null` stop attribute-only firing; source confirms `not_from`/`not_to` do too.
- FG-46: `context.user_id` is documented as "always empty" in an automation, not specifically `None`. `context` is only available in actions.
- FG-54: exact YAML from docs; `offset_type` still accepted (source); classic `trigger: sun` unaffected (docs).
- Nyx's `as_local` note (naive read as UTC) was wrong: docs say naive datetimes are treated as local time. Not merged; FG-41 now states the correct rule.

**Confirmed**

FG-44 output cap (docs errors page + source), FG-47 `states` has no membership test and `states['x']` is none for a missing entity (source + docs), FG-48 once-a-minute re-render and `delay_off` (docs), FG-51 queued `max` default 10 and dropped runs (docs), `script.turn_on` does not wait (source), FG-52 removal in 2027.10 and `config_entry_id` (source), FG-55 name-function signatures (docs), FG-56 `battery.became_low` shape (docs), admin-only actions `update.install`/`skip`/`clear_skipped`, `zwave_js` user/credential actions, `mqtt.publish`/`dump` (source), script-to-script calls share the caller's context (source), `target: exclude:` syntax (docs).

**Tested on a live install** (a test box running HA 2026.11.0, Nyx, 2026-11-11)

**Still open**

- FG-35: the HA version where reload became changed-only.
- FG-40: which release fixed it (somewhere after 2026.3.0, by 2026.11.0).
- Versions not stated in docs: when `as_datetime` gained `default`, when the 262,144-character cap was introduced.
- Next release candidate: a state condition's `for:` can't be combined with `attribute` or a helper entity as the state (docs confirm the current rule; release notes date it to 2026.10).
